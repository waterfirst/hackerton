## 3. 준비할 제안: 관측 기반 품질 검토 보조

### A안: TGV 영상에서 검사자의 검토 업무 돕기

**제안 제목:** TGV 홀 주변 결함 후보와 광학 특징을 함께 보여 주는 검사 검토 보조.

**해결할 업무 가설:** 검사자가 여러 영상을 오가며 의심 위치와 판정 근거를 기록하는 부담을 줄일 수 있는가?

- 입력: 사용이 허용된 현미경 영상. 조건이 맞으면 동일 시료·위치의 편광 영상 추가.
- 출력: 후보 위치, 광학 특징, 영상 품질 경고, 검토 순서, 사람의 판정·보류 기록.
- 대상: 결함을 검토하는 담당자. 자동 출하 판정·설비 제어·인사 평가에는 쓰지 않는다.
- 가치 가설: 검토 누락을 악화시키지 않으면서 검토시간·기록 부담을 줄일 수 있다.
- 완료 범위: 업무 흐름과 검증 가능한 적용 계획. 실제 검사 성능은 별도 데이터와 실험이 있어야 주장한다.

### 세 가지 주장을 분리한다

| 주장 | 이 준비안의 위치 | 필요한 근거 |
| --- | --- | --- |
| 현재 영상에서 의심 부위를 찾는다 | 우선 검토할 검출 보조 가설 | 독립 검토 라벨과 분리 평가 |
| 눈에 잘 보이지 않는 광학 신호를 보여 준다 | 대응 영상이 있을 때 비교할 관측 가설 | 촬영·정합·측정 조건과 신호 검증 |
| 현재 크랙이 없는 시료의 미래 크랙을 예측한다 | **미검증 장기 가설, 기본 제출 범위 밖** | 기점의 무크랙 확인, 추적 시점·부하 조건, 미래 발생 라벨, 시간 누수 방지 |

편광 패턴·복굴절 관찰은 현재 크랙 확정이나 미래 발생 예측과 동일하지 않다. “육안에 보이기 전에 예측한다”는 표현은 추적 실험 없이 성과로 쓰지 않는다. 단순 편광 명암을 정량 응력으로 환산하거나 응력 시뮬레이션을 정답 라벨로 삼지 않는다.

### 지원서 선택 문항용 문제 초안

> 유리 관통홀 주변 영상을 검토할 때 의심 위치와 판단 근거를 일관되게 기록하고 검토 순서를 정하는 업무를 다루고 싶습니다. 사용이 허용된 현미경 영상과, 확보 가능한 경우 동일 위치의 편광 관찰을 바탕으로 후보와 관측 특징을 제시하고 최종 판단은 담당자가 내리는 방안을 제안합니다. 실제 개선 효과는 별도 검증이 필요하며 회사 식별정보·기밀 수치·원본 자료는 포함하지 않습니다.

실제 지원서 질문과 본인의 경험에 맞춰 고친 뒤 사용한다. 본 문서 작성으로 제출이 이루어지지는 않는다.

## 4. 본선 문제에 적응하는 방법

### 문제 공개 후 첫 60–90분의 내부 운영안

실제 운영시간이 짧으면 비율을 줄인다.

1. 문제별 사용자, 반복 업무, 실패 비용, 제공 정보, 금지사항을 각각 한 줄로 적는다.
2. 아래 기준을 팀 내부에서 0–2점으로 평가해 지망 순서를 정한다.
   - 현장 사용자가 겪는 불편을 구체적으로 설명할 수 있는가?
   - 합법적으로 쓸 자료와 업무 근거가 있는가?
   - 사람이 확인할 입력·출력·책임을 명확히 할 수 있는가?
   - 개선 여부를 측정하는 실험을 설계할 수 있는가?
   - 남은 시간 안에 기획서로 설명할 수 있는가?
3. 배정이 끝나면 문제정의 1쪽과 범위 제외 항목을 합의한다.
4. 멘토에게 가장 불확실한 가정 3개를 확인한다. 답변이 없으면 가정으로 남긴다.

점수는 내부 의사결정 보조이며 공식 배점이 아니다. TGV와의 유사성만으로 문제를 고르거나 배정 문제를 TGV에 억지로 맞추지 않는다.

### 분야가 달라져도 유지할 공통 구조

| 배정 분야 예시 | 바꿀 대상 | 유지할 구조 |
| --- | --- | --- |
| 품질 검사 | 결함 정의·관측 단위 | 입력 검증 → 후보 → 사람 검토 → 기록 |
| 설비·생산 운영 | 작업 이력·이상 징후 | 근거 있는 후보·조치 제안, 실제 제어는 사람 승인 |
| 안전·교육 | 점검 항목·교육 상황 | 근거 표시·보류·전문가 검토. 작업 허가 자동화 제외 |
| 문서·의사결정 | 문서 출처·업무 규칙 | 근거 연결 → 초안 → 사실 확인 → 사람 승인 |

실영상이나 라벨이 없다면 업무 시나리오·화면 스케치와 검증 설계로 제출한다. 합성 예시를 쓴 경우 모든 화면에 “합성 예시, 성능 미검증”을 표시한다.

## 5. 역할 제안과 책임

공식 편성 후 팀이 합의할 역할이다. 실명과 가용시간은 작업보드에 나중에 기록한다.

| 역할 | 책임 | 반드시 남길 결과 |
| --- | --- | --- |
| 현장·문제 담당 | 현 업무, 사용자, 예외, 실패 비용 정리 | 문제정의 1쪽·업무흐름 |
| AI·데이터 담당 | 입력 조건, 방법 후보, 검증 설계 | 데이터 조건·기준선·실험표 |
| 기획·화면 담당 | 사용 시나리오, 화면 스케치, 문서 통합 | 기획서·선택 화면 |
| 검증·발표 담당 | 근거 검토, 리허설, 제출 확인 | 주장별 근거표·발표자료·제출 체크 |

3인 팀이면 기획·화면과 발표를 합친다. **작성자 외 1명이 최종 근거·보안 검토**를 한다. 한 사람이 겸임하더라도 최종 발표에 넣을 수치를 스스로만 검토하지 않도록 한다. 팀장은 결정·제출을 조율하되 모델 출력의 전문 판정 책임을 대신하지 않는다.

- 15%: 문제·사용자·기밀·규칙 확인, 배정 문제에 맞게 전환.

## 7. 필수 결과물과 완료 기준

| 결과물 | 제안 구성 | 완료 기준 |
| --- | --- | --- |
| 업무혁신 기획서 | 문제·현재 업무·제안 흐름·AI 범위·효과 검증·적용 단계·위험·출처 | 모든 효과 주장이 측정 결과/목표/가설 중 하나로 표시 |
| 발표자료 | 아래 7장 골격 | 공식 발표시간에 맞춰 조정, 한계·사람 책임 포함 |
| 근거·가정표 | 주장, 출처, 확인 수준, 추가 검증 | 출처 없는 숫자·수율 개선·예측 성능 없음 |
| 검증 계획 | [실험 계획](EXPERIMENT_PROTOCOL.md) 적용 | 기준선·평가 단위·누수·보류·중단 조건 명시 |
| 선택 화면/시연 | 입력 → 후보/근거 → 검토 → 보류/기록 | 합성 표시, 실패 경로, 수동 대안 포함 |

현 단계 결과물은 **실행계획 문서**다. 참가 접수, 현업 검증, 모델, 시연, 실제 발표 파일이 이미 준비됐다고 표현하지 않는다.

### 기획서에 채울 핵심 문장

- 사용자와 상황: “누가, 어떤 입력으로, 어떤 결정을 내리는가?”
- 현재 문제: “어느 단계에서 시간이 들거나 오류가 생기는가? 근거는 무엇인가?”
- AI 역할: “어떤 후보·정보·초안을 제공하며 무엇은 하지 않는가?”
- 개선 가설: “어떤 지표를 어떤 기준선과 비교하는가?”
- 적용 경로: “오프라인 검증 → 사람 확인 중심 시험 운영 → 별도 승인 후 제한 적용.”
- 위험 대응: “실패를 어떻게 알아차리고 사람이 어떤 대안으로 돌아가는가?”

### 발표 7장 골격

1. 문제와 사용자.
2. 현재 업무흐름과 확인된 불편 / 아직 확인할 가정.
3. 개선 업무흐름, AI 입력·출력·사람 책임.
4. 한 사례의 화면 또는 스토리보드.
5. 효과 검증: 기준선·실험·지표, 측정 결과가 없으면 검증 계획.
6. 오류·기밀·순위 편향·보류·중단 조건.
7. 적용 단계와 다음 실험.

**내부 리허설안:** 5분은 문제 40초 / 흐름 60초 / 사례 60초 / 검증 60초 / 위험·다음 단계 80초. 7분은 현 업무 근거·실험 설계·오류 사례에 2분을 추가한다. 질의는 “왜 AI인가, 데이터가 없으면, 오탐·미탐은, 효과 근거는, 회사 정보 보호는”을 준비한다. 이 시간 배분은 공식 규정이 아니다.

## 8. 선택 시연을 만들 때의 최소 범위

기획서가 완성되고 규정상 허용될 때만 착수한다. 승인된 실데이터가 없다면 합성 그림·정적 화면으로 충분하다.

- 화면 1: 입력의 출처·사용 범위, 영상 품질·정합 실패 경고.
- 화면 2: 전체 목록과 후보 오버레이. 점수는 “검토 우선 점수”, 확률로 표시하지 않음.
- 화면 3: 사람이 확인/기각/보류를 선택하고 이유 기록.
- 내보내기: 비식별 ID, 후보, 점수 의미, 사람 판정, 보류 사유. 원본·메타데이터 자동 업로드 금지.
- 기술 선택 예: 로컬 Python/OpenCV 기준선과 간단한 화면. 대규모 모델 학습이나 외부 API는 필수 아님.
- 재현 자료: 입력 예시, 실행 순서, 환경 버전, 데이터·모델 출처. 실행 오류 시 정적 화면으로 전환.

## 9. 위험과 중단·전환 기준

| 위험 | 대응 | 중단·전환 조건 |
| --- | --- | --- |
| 배정 문제와 TGV 불일치 | 공통 구조로 문제 다시 정의 | 배정 직후 TGV 고정안 포기 |
| 사용권·기밀 여부 불명 | 반입·업로드·학습·발표 중지 | 승인 자료 없으면 합성 또는 문서만 제출 |
| 라벨 부족·서로 모순 | 후보 탐색과 보류 흐름으로 축소 | 성능 수치 대신 라벨 확보 실험 제시 |
| 편광 대응·정합·보정 없음 | 현미경 단독으로 축소 | 정량 응력·융합 성능 주장 금지 |
| 미래 추적 라벨 없음 | 현재 관측 보조만 제안 | 미래 크랙 예측 주장 제외 |
| 순위가 낮은 결함이 방치됨 | 전체 목록 유지, 저순위 표본 점검, 저품질 별도 큐 | 검토 누락·보류 적체 증가 시 순위 기능 중지 |
| 모델에 대한 과신 | 근거·한계 표시, 독립 사람 판정, 최종 승인 | 자동 정상·출하·공정변경 금지 |
| 인터넷·모델·장비 실패 | 로컬 문서·PDF·정적 예시 | 새 도구 설치 대신 제출물 완성 |
| 시간 부족 | 선택 기능·시연 삭제 | 기획서·발표·위험 검토 우선 |
| 효과가 없거나 악화됨 | 불리한 결과까지 기록 | 도입 효과 주장 보류, 수동 기준선 유지 |

낮은 우선순위는 정상 판정이 아니다. 저품질 영상이나 불확실 사례를 낮은 순위로 숨기지 않고 재촬영·추가 검토 큐로 보낸다. 검토 인원·시간이 부족하면 보류량과 미검토량을 그대로 표시한다.

## 10. 근거와 공개 경계

- 공식 행사 사실은 2절의 안내를 근거로 한다. 공식 심사 배점·발표시간은 만들지 않는다.
- 기존 [기획서](HACKATHON_DRAFT.md)의 SID 논문은 공개 제목과 DOI만 참고했다. **초록·본문은 미확보**이며 실험 결과·조건·성능·그림을 가져오지 않는다.
- [DOI](https://doi.org/10.1002/sdtp.70001_564)는 관련 제목을 가리키는 참고점이지 이 제안의 검증 자료가 아니다.
- 기업 기밀은 비공개 저장소에도 올리지 않는다. 공개 논문도 원문·그림·표 재배포 권한을 따로 확인한다.
- 회사·고객·제품명, 공정 조건·치수·수율, 원본 이미지·파일명·EXIF·캡처 속 식별정보, 접근키·계정정보를 제외한다.
- 외부 AI에 자료를 넣는 것도 반출이다. 수신 서비스와 사용 범위가 승인되기 전에는 업로드하지 않는다.
- 관측, 가정 기반 계산, 합성 예시, 사람 검토, 실제 측정 결과를 파일과 발표에서 구분한다.

**첫 의사결정:** 신청 방식·참석 가능 여부와 운영사 안내 확인.  
**본선 첫 의사결정:** 배정 문제에 맞춰 이 준비안을 유지할지, 공통 구조만 가져갈지 결정.
