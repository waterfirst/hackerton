# AI 적용 설계

> v0.2 · 2026-11-08 · 구현 전 제안  
> **실제 학습 데이터·모델·성능은 아직 확보·검증되지 않았다.** 본선의 배정 문제와 허용 자료에 맞춰 아래 구조를 채택하거나 바꾼다. 공식 필수 결과물은 기획서·발표자료이며 이 문서는 AI를 어디에, 어떻게 넣을지 설명하는 설계다.

## 1. AI의 역할을 한 문장으로

현미경 영상의 홀 주변에서 **결함 의심 위치와 검토 순서의 후보**를 제시하고, 사람이 원본·광학 특징·불확실성을 보고 최종 판정과 다음 행동을 결정한다.

현재 영상에 담긴 정보로 후보를 찾는 검출 보조가 기본이다. “앞으로 크랙이 생긴다”는 미래 예측은 추적 자료와 별도 실험이 필요한 장기 가설이다.

## 2. 입력에서 최종 기록까지

| 단계 | 구체 처리 | 실패 시 처리 | 출력 |
| --- | --- | --- | --- |
| ① 자료 확인 | 출처·사용권·비식별 ID·촬영 정보 확인, 허용 영상만 로컬 입력 | 권한 불명은 처리하지 않음 | 사용 가능/불가 상태 |
| ② 품질 확인 | 초점·노출·가림·스케일 정보 점검. 기준은 촬영 조건별 검토 | 재촬영·사람 확인 큐로 분리 | 품질 상태·사유 |
| ③ 홀/ROI 지정 | 원·윤곽 기반 홀 탐색, 주변 ROI 추출. 사람이 수정 가능 | 자동 위치 실패는 수동 ROI | 홀 ID·원본 좌표·ROI 변환 |
| ④ 후보 생성 | 먼저 규칙 기준선, 라벨 조건 충족 시 지도학습 모델 비교 | 입력 범위 밖·모델 오류는 보류 | 후보 박스/영역·점수·방법 버전 |
| ⑤ 조건부 정보 결합 | 대응 편광 영상의 정합·특징을 별도로 보여 줌 | 정합 실패면 결합 중지 | 정합 상태·광학 특징 |
| ⑥ 검토 순서 제안 | 유효 영상의 후보 점수로 순서 제시, 동일 점수는 접수 순 | 저품질·불확실성은 별도 큐 | 후보 순서·이유·미검토 수 |
| ⑦ 사람 판정 | 원본과 오버레이 비교, 확인/기각/보류 및 사유 기록 | 판단 불가면 추가 관찰 | 검토자 판정·근거·후속 행동 |
| ⑧ 기록·개선 | 비식별 결과 내보내기, 승인된 판정만 라벨 후보로 축적 | 승인 없는 자료는 학습 제외 | 감사 기록·다음 학습 후보 |

품질 불량을 점수에서 빼서 아래로 보내지 않는다. **낮은 점수·목록 하단·후보 없음 모두 정상 판정이 아니다.** 원본 목록과 사람 검토 상태를 항상 유지한다.

## 3. 데이터와 라벨을 무엇으로 만들 것인가

### 입력 단위

- 기본 단위: 비식별 시료 → 홀 → 영상 → ROI. 같은 시료·홀의 사진은 평가에서 독립 표본처럼 흩어 놓지 않는다.
- 현미경 영상: 원본 해상도, 스케일·촬영 조건은 승인 가능한 범위에서 기록한다.
- 편광 영상: 같은 시료·위치임을 나타내는 pair_id, 방향·광학 배치·정합 상태가 필요하다.
- 파일명·EXIF·화면 주석의 기밀을 제거한다. 원본을 외부 AI에 자동 전송하지 않는다.

### 라벨 수준에 따라 문제를 선택

| 확보 가능한 라벨 | 가능한 과제 | 한계 |
| --- | --- | --- |
| 홀/ROI별 확인 크랙·관측상 없음·판정 불가 | ROI 분류 | 위치를 정확히 찾았다고 주장할 수 없음 |
| 전문가 후보 박스·선 위치와 확인 상태 | 위치 검출 | 매칭 거리/영역 규칙 필요 |
| 경계가 확인된 픽셀 마스크 | 분할 | 작은 경계 차이·검토자 불일치 반영 필요 |
| 판정이 없는 영상만 있음 | 규칙 기반 탐색·사용성 검토 | 정확도·재현율 검증 불가 |

먼지·스크래치·홀 가장자리 반사·초점 불량 같은 혼동 사례를 따로 태깅한다. 후보 위치와 “실제 크랙 확인”을 같은 라벨로 취급하지 않는다. 라벨 기준과 불일치 처리 절차는 [실험 계획](EXPERIMENT_PROTOCOL.md)을 따른다.

## 4. 규칙 기준선과 AI 모델 선택

### 4.1 먼저 만들 비교 기준선: 규칙 기반 영상처리

1. 승인된 방법으로 밝기·대비를 정규화하고 필요한 경우 잡음을 줄인다.
2. 홀 위치와 경계 주변의 ROI를 정한다. 원형이 아닌 홀은 수동 또는 다른 윤곽 방법을 쓴다.
3. 에지·방향성 필터·연결 요소로 선형 후보를 찾는다.
4. 후보의 길이·형상·대비와 홀 경계와의 관계를 기록한다. 반사·스크래치도 후보가 될 수 있음을 남긴다.
5. 검증 세트에서 기준값을 정하고 평가 세트에는 고정한다.

이 방법은 **비교용 규칙 기준선**이다. AI 학습 모델로 포장하지 않는다. 실제 스케일 정보가 없으면 길이를 물리 단위로 표시하지 않는다.

### 4.2 라벨이 충분할 때: 지도학습 후보

- 분류 라벨만 있으면 ROI 분류부터 시작한다. 사용 가능한 공개 사전학습 특징 + 단순 분류기 또는 소형 CNN을 비교 후보로 둔다.
- 위치 라벨이 있으면 경량 검출 모델, 픽셀 마스크가 있으면 소형 U-Net 계열 분할을 검토한다. 특정 모델의 성능을 미리 보장하지 않는다.
- 사전학습 모델·라이브러리의 출처, 라이선스, 다운로드·행사 사용 허용 여부를 확인한다.
- 증강은 학습 세트 안에서만 한다. 회전·밝기 변형이 실제 촬영 변화와 맞는지 확인하고 편광 방향 의미를 임의로 지우지 않는다.
- 충분한 데이터의 기준은 임의의 이미지 수가 아니다. 독립 시료 수, 양성·혼동 사례, 그룹별 성능과 학습 곡선으로 판단한다.
- 소형 모델부터 시작하고 규칙 기준선보다 독립 평가에서 나아지는지 확인한다. 성능이 같거나 나쁘면 기준선을 유지한다.

분류 모델의 주목도 그림은 설명 참고일 뿐 크랙 위치 정답이나 인과 근거가 아니다. 정밀한 위치가 필요하면 적절한 위치 라벨과 검출/분할 검증이 필요하다.

### 4.3 라벨이 적거나 없을 때

- 우선 규칙 후보 + 사람 검토, 수동 ROI, 정적 스토리보드로 범위를 줄인다.
- 확실하게 검토한 정상 사례가 충분하면 특징 거리·이상탐지 방법을 탐색할 수 있다. 이상 점수는 크랙 확률이 아니며 오염된 정상군·촬영 변화에 취약하다.
- 라벨이 전혀 없으면 모델 우수성을 평가하지 않는다. 대표 사례와 판정 기준을 만드는 것이 우선이다.
- 합성 영상은 UI·파일 처리·실패 경로 테스트에 사용한다. 합성에서 좋아 보인 결과를 실제 검사 성능으로 옮겨 쓰지 않는다.
- 추가 라벨을 요청할 때 어려운 사례만 뽑지 말고 무작위 표본도 포함한다. 별도의 평가 세트는 새 학습 라벨로 재사용하지 않는다.

## 5. 후보·우선순위·불확실성을 화면에 표현

각 후보에는 다음을 함께 표시한다.

- 비식별 시료·홀·영상 ID와 원본 좌표의 박스/선/영역.
- 후보 생성 방식: 규칙 / 분류 / 검출 / 분할 / 탐색용 이상 점수.
- 점수의 의미와 사용 버전. 검증·보정되지 않은 점수에는 % 확률 표시를 하지 않는다.
- 품질 부족, 정합 실패, 새로운 촬영 조건, 모델 오류, 임계값 근처 등 검토가 필요한 이유.
- 사람 판정과 보류 이유, 남은 검토 수.

제안 순서는 **유효 영상에서 후보가 강한 순으로 먼저 확인**하는 보조 기능이다. 중대도·파손 위험·미래 발생 확률과 같지 않다. 조건별 점수 범위가 다르면 서로 다른 장비·모델 점수를 그대로 섞지 않는다.

안전장치:
1. 품질 불량·입력 범위 밖 사례는 별도 추가 검토 큐에 넣는다.
2. 저순위 표본도 독립적으로 점검하고 누락 위험을 측정한다.
3. 사람은 모든 원본 목록을 볼 수 있고 순서를 무시·수정할 수 있다.
4. 보류·미검토량을 숨기지 않는다. 시간 안에 다 못 보면 미완료로 보고한다.
5. 불확실성 점수도 실제 오류와의 관계를 검증하기 전에는 정확한 신뢰도로 부르지 않는다.

## 6. 편광 영상은 조건부 확장으로

- 시작은 현미경과 편광을 나란히 보여 주는 방식이다. 정합 정확도와 광학 조건이 확인된 뒤 특징 결합을 검토한다.
- 가능하면 동일 ROI의 명암·방향성·패턴 특징을 분리 추출해 현미경 특징에 추가하는 단순 모델부터 비교한다.
- H2 비교는 **동일한 대응 표본·같은 분할**에서 현미경 단독과 결합 방법을 평가한다.
- 편광 영상이 없는 시료, 정합 실패, 촬영 조건 변화는 별도 기록한다. 결과가 좋은 짝만 골라 일반화하지 않는다.
- 보정·광학 측정·물성 근거 없이 명암을 정량 복굴절·잔류응력 값으로 환산하지 않는다.
- 실제 이점이 없거나 영상 확보 비용이 크면 현미경 단독안을 채택한다.

## 7. 사람 판정에서 모델 업데이트까지

**온라인 자동 학습은 하지 않는다.**

1. 사람 판정을 임시 검토 기록으로 저장한다.
2. 라벨 책임자가 근거·불일치·사용권을 확인한 것만 새 라벨 버전으로 승인한다.
3. 데이터 버전·분할·설정·코드·모델 버전을 묶어 오프라인에서 재학습한다.
4. 기존 모델·규칙 기준선과 고정 평가로 비교한다. 반복해서 본 평가 세트는 추후 새 평가로 보완한다.
5. 독립 검토자가 누락·오탐·보류·집단별 촬영 조건의 변화를 검토한다.
6. 현장 책임자의 명시적 승인 후 제한된 버전을 배포한다.
7. 악화 시 이전 버전 또는 수동 업무로 되돌린다. 기존 판정 기록은 새 모델로 조용히 덮어쓰지 않는다.

검토자가 AI 결과를 그대로 승인한 기록만 학습하면 오류가 되풀이될 수 있다. 독립 라벨과 무작위 표본 점검으로 이를 줄인다.

## 8. 독립 평가와 현장 적용 순서

| 단계 | 목적 | 다음 단계 조건 |
| --- | --- | --- |
| 문서/합성 시연 | 업무 흐름·실패 처리 확인 | 기밀·규칙·사람 책임 검토 |
| 승인 자료의 오프라인 평가 | 기준선 대비 효과와 오류 확인 | 사전 지표·표본·누수·보류를 포함한 결과 |
| 그림자 운영 | 실제 판단에 영향 없이 기존 업무와 비교 | 누락·시간·입력 변화·검토 부담 허용 여부 |
| 제한된 보조 운영 | 담당자가 항상 확인하는 범위에서 사용 | 현장·보안 승인, 사용자 교육, 기록·복구 절차 |
| 후속 확장 | 별도 데이터·독립 검증 | 별도 승인과 실제 효과 근거 |

공장 시스템 연결, 클라우드 반출, 자동 출하 판정, 공정 조건 변경은 이 계획에 포함되지 않는다. 로컬·오프라인 처리를 우선 제안하되 실제 배포 장소·보관 기간·접근 권한은 데이터 소유자와 승인한다.

## 9. 생성형 AI를 쓸 수 있는 보조 영역

행사 규정과 자료 반출 승인이 있을 때, 비기밀 텍스트의 업무흐름 정리·검토 메모 초안·발표 문장 점검에 활용할 수 있다. 출처가 있는 문장만 쓰고 사람이 사실을 확인한다.

이미지에 대해 언어모델이 그럴듯한 설명을 했다는 이유로 크랙 라벨, 실제 응력, 성능 수치, 원인·미래 예측의 근거로 쓰지 않는다. 근거 없는 수치나 회사 정보를 생성해 기획서를 채우지 않는다.

## 10. 현 단계 완료 상태

- 작성됨: AI 적용 위치, 데이터·라벨 조건, 규칙/학습 대안, 후보·보류·우선순위, 사람 승인 업데이트, 검증·배포 계획.
- 미완료: 데이터 확보·승인, 라벨링, 모델 구현·학습, 독립 평가, 현장 적용·효과 측정.
