# TGV 품질 AX 해커톤 기획서

> v0.1 / 검토용 제안 / 2026-11-08  
> 공식 문제는 행사 당일 공개되는 것으로 이해하고 준비합니다. 아래 과제·일정·평가 배점은 준비안이며, 행사 공지와 제공 데이터에 맞춰 수정합니다. 팀 구성과 개인별 역할은 아직 확정하지 않습니다.

## 1. 한 문장 제안

유리 패키징 TGV 홀 주변 현미경 영상에서 크랙 의심 부위를 표시하고, 편광 영상이 있으면 관련 광학 특징을 함께 보여 주어 전문가의 검토 순서를 돕는 시연 도구를 만든다.

## 2. 해결할 문제와 사용자

- 대상 사용자: 홀 주변 결함을 검토하는 품질·공정·분석 담당자.
- 준비 단계의 가설: 반복 관찰에서 의심 부위와 근거를 일관되게 기록하고 검토 순서를 정하면 검사 업무를 도울 수 있다.
- 실제 현장의 시간 절감, 누락률 개선, 공정 수율 향상은 현재 확인되지 않았다. 별도 실험 없이 성과로 제시하지 않는다.
- 출력은 “크랙 후보 / 검토 필요 / 판정 보류” 중심이다. 자동 출하 판정이나 공정 조건 변경은 범위에서 제외한다.

## 3. 기술 접근과 우선순위

### A. 기본 과제: 현미경 영상 검사 보조

1. 촬영 품질 확인: 초점, 노출, 배율·스케일 정보, 가림 여부.
2. 홀 위치와 주변 관심영역(ROI) 표시. 자동 위치 추정이 불안정하면 수동 ROI를 허용.
3. 선형 결함 후보를 찾는 간단한 영상처리 기준선부터 구성.
4. 승인된 라벨 데이터가 충분할 때 분류·검출·분할 모델 중 하나를 선택.
5. 후보 위치, 모델 점수, 입력 품질 경고와 판정 보류 사유를 표시.
6. 검토자가 후보를 확인·기각하고 근거를 남길 수 있게 구성.

스크래치, 먼지, 홀 경계 반사, 초점 불량 등을 크랙으로 오인할 수 있다. 모델 점수는 검증·보정 전까지 크랙 확률로 표시하지 않는다.

### B. 조건부 확장: 편광·복굴절 관찰

동일 시료·동일 위치의 대응 영상과 촬영 조건을 확보했을 때 진행한다.

- 편광자·검광자 배치, 조명, 시료 방향·두께 등 확인 가능한 조건을 기록.
- 현미경 ROI와 편광 영상을 정합하고 정합 실패를 별도로 표시.
- 편광 관찰에서 얻은 명암·패턴 특징과 현미경 크랙 후보를 나란히 표시.
- 편광 영상 추가가 도움이 되는지 동일한 평가 분할에서 현미경 단독 기준선과 비교.
- 단순 편광 명암을 정량 복굴절·응력 값으로 환산하지 않는다. 정량화에는 별도의 광학 측정·보정과 물성 정보가 필요하다.

복굴절 관련 신호는 응력 외에도 재료·광학 배치·두께 등 여러 요인의 영향을 받을 수 있다. 특정 패턴만으로 크랙 존재나 원인을 단정하지 않는다.

### C. 후순위 탐색: 응력 시뮬레이션

- 공개·사용 승인된 물성, 단순화한 홀 형상과 명시적인 경계조건만 사용.
- 형상·하중·재료 가정을 바꿨을 때 응력 집중 위치가 어떻게 달라지는지 비교.
- 출력 화면에 “가정 기반 시뮬레이션”을 명시하고 실제 관측 영상과 분리.
- 응력 최대 위치를 실제 크랙 정답 라벨로 사용하지 않는다.
- 실제 잔류응력 재현, 균열 성장 예측, 파괴 기준 검증은 별도 과제다.

### 데이터 상황별 선택

| 행사 당일 확보 자료 | 수행 범위 | 주장할 수 없는 내용 |
| --- | --- | --- |
| 승인된 현미경 영상 + 검토 라벨 | A 및 제한된 평가 | 공정 전체 성능·양산 적용성 |
| 대응 편광 영상까지 확보 | A + B 비교 | 보정 없는 정량 응력·인과관계 |
| 라벨이 부족한 실영상 | 후보 탐색과 사람 검토 흐름 | 정확도·재현율의 신뢰성 있는 일반화 |
| 실영상 사용 불가 | 합성 예제 기반 인터페이스 시연 | 실제 크랙 검출 성능 |
| 승인된 물성·형상·해석 조건 확보 | C의 가정별 비교 | 실험 검증 없는 실제 응력·파괴 예측 |

## 4. 데이터와 라벨 설계

### 최소 데이터 기록

| 필드 | 의미 |
| --- | --- |
| sample_id / hole_id / image_id | 비식별 시료·홀·영상 식별자 |
| modality | 현미경 / 편광 / 합성 등 |
| pair_id | 대응 영상 묶음. 대응하지 않으면 비워 둠 |
| acquisition_notes | 승인된 범위의 촬영·보정 조건과 품질 이슈 |
| label / annotation | 전문가 확인 상태와 후보 위치·영역 |
| review_status | 미검토 / 검토 완료 / 의견 불일치 / 판정 불가 |
| source / usage_permission | 출처, 라이선스 또는 사용 승인 범위 |
| split_group | 동일 시료·홀·취득 묶음을 식별하는 분할 그룹 |

촬영 조건 자체가 기밀이면 기록·공유하지 않는다. 원본 파일명, EXIF, 화면 주석과 경로에도 기밀 식별정보가 있는지 확인한다.

### 라벨링 원칙

- 후보 표시와 실제 크랙 확인을 별도 상태로 기록한다.
- 가능하면 두 검토자의 독립 판정과 불일치 조정 절차를 둔다.
- 현미경만으로 확인이 어려운 사례는 판정 불가로 남기고 필요 시 추가 관찰 대상으로 분리한다.
- 합성 이미지에는 합성 표시를 붙이고 실제 이미지 평가와 섞지 않는다.
- 라벨 기준과 관찰 한계를 데이터 문서에 남긴다.

## 5. MVP 기능과 시연

### 필수 기능 제안

- 허용된 이미지 선택 및 입력 품질 확인.
- 원본과 후보 오버레이의 비교.
- 홀별 후보 목록과 검토 우선순위.
- 판정 보류 및 사람의 확인·기각 기록.
- 이미지 ID, 후보 위치, 점수 의미, 검토 결과를 담은 CSV 요약.

검토 우선순위는 후보 점수와 영상 품질을 설명 가능한 규칙으로 구성한다. 낮은 점수 때문에 자동으로 정상 처리하지 않는다. 흐릿한 영상은 재촬영·추가 검토 대상으로 분리한다.

### 3분 시연안

1. 문제와 입력 데이터의 허용 범위를 설명한다.
2. 정상처럼 보이는 예시, 결함 의심 예시, 판정이 어려운 예시를 각각 보여 준다.
3. 후보 위치와 근거를 확인하고 사람이 검토 결과를 기록한다.
4. 편광 영상이 있으면 동일 위치 비교를 보여 준다.
5. 오류 사례와 남은 검증 과제를 설명한다.

## 6. 평가 계획

### 분할과 누수 방지

- 동일 시료의 홀, 같은 홀의 여러 배율·방향 영상, 증강본을 서로 다른 학습·평가 세트에 나누지 않는다.
- 가능한 경우 시료 또는 제조·취득 묶음 단위로 분할하고 분할 기준을 명시한다.
- 임계값 선택은 검증 세트에서 수행하고 최종 평가 세트는 별도로 둔다.
- 데이터가 너무 작으면 학습 성능과 독립 평가를 구분하며, 안정적인 성능 추정이 불가능하다고 적는다.

### 보고 지표

- **홀 단위**: 크랙 확인 홀 재현율, 정밀도, 정상 홀의 오경보 비율, 혼동행렬.
- **위치 검출**: 전문가 표식과의 매칭 기준을 먼저 정하고 평가. 분할 라벨이 있으면 Dice 또는 IoU를 보조 지표로 사용.
- **보류**: 전체 중 판정 보류 비율과 보류를 포함한 검토 부담을 함께 보고.
- **업무 흐름**: 같은 사례를 수동·보조 방식으로 검토할 때의 시간과 판단 일관성을 소규모 탐색 평가.
- **실행 조건**: 장치, 해상도, 전처리 포함 여부와 영상당 처리 시간.

각 수치에는 평가 표본 수와 양성·음성 수를 함께 적는다. 보류 사례를 조용히 제외하거나, 합성 예제 성능을 실데이터 성능처럼 합산하지 않는다. 극소수 사례는 개별 결과를 제시하고 일반화하지 않는다.

### 비교 실험

1. 간단한 영상처리 기준선.
2. 데이터가 허용하는 경우 현미경 영상 AI 모델.
3. 대응 영상이 있는 경우 현미경 + 편광 특징 결합 모델.
4. 어떤 특징이 도움을 주는지와 오탐·미탐 원인을 함께 분석.

목표 정확도나 수율 개선 수치는 미리 약속하지 않는다. 정량 목표는 데이터 규모·결함 정의·비교 기준 확인 후 합의한다.

## 7. 구현 구성 제안

- Python 기반 영상 처리와 결과 기록.
- 데이터 조건에 따라 OpenCV 기준선 및 적절한 학습 프레임워크 검토.
- 로컬 시연용 간단한 웹 화면을 선택할 수 있다.
- 환경 파일, 실행 순서, 입력 형식, 모델·데이터 출처를 함께 제출.
- 설치·다운로드·외부 AI 서비스 이용은 행사 규칙과 데이터 반출 허용 범위를 먼저 확인.
- 이 초안에는 실행 코드, 모델 가중치, 실제 데이터가 아직 없다.

## 8. 행사 당일 운영안

아래는 **총 작업 시간 대비 비율을 사용한 제안**이다. 실제 행사 시간표와 팀 규모에 맞춰 조정한다.

| 단계 | 시간 비율 제안 | 완료 기준 |
| --- | --- | --- |
| 문제 공개 확인·팀 합의 | 10% | 공식 문제와 본 준비안의 적합성 결정 |
| 데이터·권한·라벨 점검 | 15% | 사용 가능 자료와 평가 단위 확정 |
| 기준선·최소 화면 구현 | 30% | 한 사례의 전체 처리 흐름 작동 |
| 검증·오류 분석 | 25% | 분리 평가 결과 또는 평가 불가 사유 기록 |
| 발표·재현 점검 | 20% | 시연, 한계, 실행 안내 정리 |

팀 역할은 도메인·라벨 기준, 데이터·모델, 화면·연동, 검증·발표로 나눌 수 있다. 한 사람이 여러 역할을 맡을 수 있으며, 특정인의 참여나 담당을 이 문서에서 확정하지 않는다.

## 9. 제출물 제안

1. 문제 정의와 범위를 담은 한 페이지 요약.
2. 실행 가능한 최소 시연 또는 실데이터 부재 시 명확히 표시된 합성 시연.
3. 데이터 출처·허용 범위·분할·라벨 정의 문서.
4. 기준선 대비 결과, 오탐·미탐·판정 보류 사례.
5. 재현 방법, 한계와 후속 실험 계획.
6. 발표 자료: 문제 → 관측 정보 → 방법 → 시연 → 평가 → 한계와 다음 단계.

### 팀 내부 검토 기준 제안

공식 심사 기준이 아니다. 문제 적합성 20, 데이터·검증 타당성 30, 시연 완성도 20, 업무 활용 가능성 15, 재현성·정보보호 15의 100점 기준으로 준비 상태를 점검할 수 있다.

## 10. 공개 자료와 근거의 경계

- 관련 공개 제목: **Stress-Induced Birefringence Measurement for Crack Detection in Bessel Beam Laser-Drilled Glass**
- DOI: https://doi.org/10.1002/sdtp.70001_564
- 제목은 공개 SID 프로그램에서 확인된 정보에 근거한다. 본 초안 작성 시 논문 본문과 초록을 확보하지 못했다.
- 따라서 위 논문의 실험 방법·조건·정확도·검출 한계나 결론을 이 기획의 검증 근거로 사용하지 않는다.
- 본 문서의 모델 선택, 시연 구성, 지표, 운영안은 해커톤 준비를 위한 제안이다.
- 논문이 공개되어 있어도 그림·표·원문 재배포 권한이 자동으로 부여되는 것은 아니다.
