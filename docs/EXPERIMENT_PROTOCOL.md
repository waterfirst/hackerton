# 실험·검증 계획

> v0.2 · 2026-11-08 · 실행 전 설계  
> 아직 실데이터·실험 결과·성능 수치가 없다. 아래는 제안 절차이며 합격 성능을 약속하지 않는다. 아이디어 해커톤에서는 이 검증 설계 자체를 설명하고, 실제 실험은 자료와 시간이 허용할 때 수행한다.

## 1. 검증 질문과 범위

| ID | 질문 | 검증 가능 조건 | 조건이 없으면 |
| --- | --- | --- | --- |
| H1 | 현미경 후보 표시가 수동 검토보다 누락을 악화시키지 않으면서 시간을 줄이는가? | 승인된 영상, 독립 판정, 검토자 | 업무흐름 시연·측정 계획만 제시 |
| H2 | 대응 편광 특징이 현미경 단독보다 검토에 추가 정보를 주는가? | 동일 시료·위치 대응, 촬영·정합 조건, 같은 평가 표본 | 현미경 단독 범위 |
| H3 | 기점 신호가 이후 크랙 발생과 관련이 있는가? | 기점 무크랙 확인, 추적 자료, 부하·기간, 사건 라벨 | 미검증 장기 가설로 남김 |

H1과 H2가 확인되어도 H3가 성립하는 것은 아니다. H3의 연관성이 관측되어도 원인이나 공정 개선 효과를 증명한 것은 아니다.

## 2. 시작 전 고정할 실험 카드

실험 전에 빈칸을 채우고 평가 결과를 본 뒤 기준을 바꾸지 않는다. 바꾸면 새 실험 ID를 만든다.

- 실험 ID / 작성일 / 담당 / 검토자:
- 검증 가설 및 제외할 주장:
- 자료 출처 / 사용·저장·학습·발표·재배포 허용 범위:
- 시료 수 / 홀 수 / 영상 수 / 양성·음성·판정 불가 수:
- 평가 단위와 라벨 기준 / 검토자 불일치 처리:
- 학습·검증·평가 분할 및 고정 seed / 시료·취득 그룹:
- 기준선 / 비교 방법 / 사용할 특징:
- 임계값 선택 방법 / 보류 규칙 / 위치 매칭 기준:
- 주지표 / 보조지표 / 허용 악화 폭 / 최소 의미 있는 개선:
- 표본수 근거 / 신뢰구간 방법 / 반복 조건:
- 중단 조건 / 실제 실행 환경 / 소요시간:
- 결과 경로 / 코드·설정 버전 / 한계:

허용 악화 폭과 최소 개선 폭은 현장 담당자가 오류 비용·기존 업무 수준을 보고 실험 전에 정한다. 값이 정해지지 않았거나 표본이 부족하면 “도입 가능” 결론을 내리지 않는다.

## 3. 데이터·라벨·분할

### 최소 데이터 열

`sample_id, hole_id, image_id, modality, pair_id, acquisition_group, captured_at, source, permission_scope, label, label_basis, review_status, split_group, split`

- ID는 비식별화한다. 기밀인 취득 시각·조건은 승인된 범위 밖으로 기록하지 않는다.
- 상태는 확인 크랙 / 관측상 크랙 없음 / 판정 불가를 구분한다. “관측상 없음”은 검출한계 아래 결함까지 없다는 뜻이 아니다.
- 가능하면 모델 결과를 보지 않은 두 검토자가 독립 판정한다. 불일치·보류는 제3 검토나 추가 관찰로 처리하며 억지로 정답을 만들지 않는다.
- 동일 시료, 홀의 다른 배율·방향, 대응 모달리티, 연속 촬영·증강본은 같은 분할 그룹에 둔다. 상관이 큰 제조·취득 묶음까지 그룹화할 수 있으면 그렇게 한다.
- 학습은 학습 세트, 임계값·특징 선택은 검증 세트, 최종 보고는 고정 평가 세트에서 한다.
- 표본이 작으면 그룹 교차검증을 탐색 결과로 보고한다. 평가 세트를 보며 튜닝한 결과는 독립 검증으로 부르지 않는다.
- 합성 예시와 실영상 평가를 합산하지 않는다. 정합 성공 사례만 고르면 제외 수·이유를 공개한다.

## 4. 비교 실험 순서

| 단계 | 비교 | 공정하게 맞출 조건 | 남길 결과 |
| --- | --- | --- | --- |
| E0 | 현재 수동 업무 | 동일 업무 정의·종료 기준 | 기준 시간, 누락·보류·기록 부담 |
| E1 | 간단한 영상처리 기준선 | 같은 평가 분할·라벨·입력 품질 | 홀 단위 결과, 오탐·미탐 |
| E2 | 현미경 AI 후보 표시 | 충분한 승인 라벨이 있을 때만, 동일 분할 | E1 대비 결과와 실패 사례 |
| E3 | 현미경 단독 vs 편광 추가 | 동일 대응 표본, 같은 튜닝 예산·평가 방식 | 추가 정보의 효과와 정합 실패 |
| E4 | 사람 단독 vs 사람+보조 | 검토 난이도·순서·학습효과 통제 | 시간과 품질을 함께 비교 |
| E5 | 미래 발생 추적 | 아래 7절 조건을 만족할 때만 별도 연구 | 해커톤 현재 성능과 분리 |

데이터나 시간이 부족하면 E0의 관찰 계획과 E1의 설계까지만 제출한다. 모델 복잡도를 늘리는 것이 필수 완료 조건은 아니다.

## 5. 지표 정의와 보고 규칙

### 영상·홀 기준

- 재현율 = TP / (TP + FN). “확인 크랙” 중 후보로 찾아 검토에 전달한 비율.
- 정밀도 = TP / (TP + FP). 후보로 올린 것 중 확인 크랙 비율.
- 오경보율 = FP / (FP + TN). 관측상 음성 홀 중 후보로 표시된 비율.
- 위치 지표는 검토자가 정한 거리·영역 매칭 기준을 사전에 고정한다. 분할 라벨이 있을 때만 Dice/IoU를 사용한다.
- 점수가 보정되지 않았다면 확률이 아니라 순서용 점수라고 명시한다.

### 보류·누락·순위

- 전체 수 = 평가 가능한 판정 수 + 보류 수. 보류 이유와 양성 포함 여부를 별도 표로 남긴다.
- 자동 후보 전달 재현율은 보류된 양성을 분자에 넣지 않는다. “후보 또는 보류로 사람에게 전달된 비율”은 별도 지표로 구분한다.
- 보류 중 판정이 가능한 사례의 오류를 따로 보고하고, 판정 불가 사례는 분모와 제외 사유를 밝힌다. 보류를 정상으로 간주하지 않는다.
- 전체 목록에서 상위 k개를 본 후 찾은 양성 비율과 저순위에 남은 양성 수를 함께 본다. k는 검토 가능량을 근거로 사전 정의하며, 이것만으로 전체 재현율을 대신하지 않는다.
- 검토 순위의 실제 효과는 미검토량·보류 적체·처리 완료시간과 함께 평가한다.

### 업무·실행

- 검토시간: 사례 열기부터 사람 판정·기록 완료까지. 입력 준비·실패 복구 포함 여부 명시.
- 최종 사람 판정의 누락, 오탐, 의견 불일치, 재촬영·추가 관찰 비율.
- 시스템 처리시간: 장치·해상도·전처리 포함 여부, 중앙값과 지연 분포.
- 비용: 허용된 견적이나 실제 측정이 있을 때만 계산. 추정은 가정·단가·범위를 함께 표시.
- 업무 절감 추정 = 사례당 수동시간과 보조시간의 차이 × 검토량 − 추가 검증·유지보수 부담. 실측이 없으면 숫자를 채우지 않는다.

모든 수치에 시료/홀/영상 수, 양성/음성/보류 수, 분할 방식, 버전, 불확실성을 붙인다. 홀들이 같은 시료에 속하면 독립 표본으로 과대 계산하지 않는다. 가능하면 시료 그룹 단위 bootstrap 신뢰구간을 쓰되 표본이 너무 작으면 개별 사례와 한계를 제시한다. 결과가 없으면 공란 또는 “미측정”이며 0으로 쓰지 않는다.

## 6. 사람 단독·보조 비교 설계

1. 가능하면 비슷한 난이도의 사례를 묶어 무작위 배정하고 검토자·제시 순서를 균형화한다.
2. 동일 사례를 두 번 보면 기억 효과가 생긴다. 다른 사례 묶음 또는 충분한 간격의 교차 설계를 선택하고 한계를 기록한다.
3. 참조 라벨은 보조 화면의 결과와 독립적으로 만든다. 검토자에게 참조 정답을 미리 보여 주지 않는다.
4. 모델 실패·보류 사례도 포함한다. 성공 사례만 골라 시간 절감을 계산하지 않는다.
5. 순위가 오히려 누락을 만드는지 확인하기 위해 저순위 표본을 독립 검토하고, 제한된 평가에서는 전체 정답과 대조한다.
6. 속도가 좋아져도 중요한 결함 누락·최종 오류가 사전 합의한 허용 범위를 넘으면 실패로 판정한다.
7. 참여자가 적으면 사용성 탐색으로 표시한다. 양산 검사 효과나 전체 조직의 절감으로 일반화하지 않는다.

## 7. 미래 크랙 예측을 별도로 검증하려면

이 절은 후속 연구 조건이다. 현재 확보되었다고 가정하지 않는다.

- 기점 t0에서 정해진 관찰법·검출한계로 크랙이 관측되지 않은 시료를 기록한다.
- 예측 입력은 t0 또는 이전 정보로 제한한다. 발생 후 사진, 사후 판정, 미래 공정 정보를 특징에 넣지 않는다.
- 추적 기간, 부하·열 이력 등 승인된 조건, 관측 간격과 사건 정의를 사전 지정한다.
- 미래 크랙 발생/미발생, 발생 시점 또는 구간, 추적 중단·검열 상태를 남긴다.
- 학습·평가를 시료·취득 그룹과 시간 기준으로 분리한다. 같은 시료의 미래 영상을 학습에 섞지 않는다.
- 목표 시점의 사건 예측 또는 시간-사건 분석 중 실제 데이터에 맞는 방법을 고른다. 불균형·검열·추적 길이를 반영한다.
- 단순 기준선과 비교하고 신뢰구간·외부 재현을 검토한다. 관측 신호가 선행했다는 사실만으로 인과성·예방 효과를 주장하지 않는다.

이 조건이 충족되지 않으면 발표 제목과 결론은 “현재 관측·검토 보조” 범위에 둔다.

## 8. 주장·결과 기록 양식

| 주장 ID | 문장 | 구분 | 근거/실험 ID | 확인 수준·한계 |
| --- | --- | --- | --- | --- |
| C-01 | 후보와 근거를 모아 검토를 도울 수 있다 | 가설 | H1 / 실행 전 | 실제 시간·누락 영향 미검증 |
| C-02 | 편광 추가가 정보를 보완할 수 있다 | 가설 | H2 / 실행 전 | 대응 영상·라벨 필요 |
| C-03 | 미래 크랙을 예측한다 | 검증되지 않은 주장 | H3 / 실행 전 | 기본 결과·효과로 사용 금지 |

실험 기록에는 실행 상태(미실행/실행/중단), 입력 버전, 분할, 설정, TP/FP/FN/TN, 보류, 시간, 실패 사례, 결론을 남긴다. 승인 전 원본·기밀 데이터를 이 저장소의 예시 표에 넣지 않는다.

## 9. 검증 완료와 적용 판단

- 문서 완료: 실험 카드, 지표·누수·보류·중단 기준을 다른 사람이 이해할 수 있다.
- 탐색 실험 완료: 허용된 자료로 기록을 남겼으나 일반화·현업 적용은 미확정이다.
- 제한된 효과 근거: 사전에 정한 비교를 수행하고 오류·불확실성까지 보고했다.
- 실제 적용: 독립 검증, 보안·현장 승인, 책임·모니터링·수동 복귀 절차가 추가로 필요하다.

어느 단계인지 명시한다. **이 문서의 현재 상태는 첫 단계의 설계이며 실험 완료가 아니다.**
