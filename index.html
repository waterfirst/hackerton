Process / 20-second concept

유리 홀 가공부터 최종 검사까지.

다섯 단계를 20초 GIF로 살펴봅니다. 검사 단계에 앞서 설명한 후보 표시·사람 검토 흐름을 적용할 수 있다는 설계 구상이며, 실제 공정 영상이나 성능 검증 결과가 아닙니다.

정지 개념도 · 자바스크립트 사용 시 20초 GIF 재생 가능

  1. 유리 레이저 홀 가공
  2. 검사
  3. Cu 도금

  5. 최종 검사

Cu가 홀 내부 전체를 채우는 충전형 비아 개념도입니다. CMP는 표면의 과잉 Cu를 제거하며, 홀 내부의 Cu 충전은 유지됩니다. 세정·전처리·시드층 등 세부 단계와 실제 형상·비율·조건은 생략했습니다. 공정 순서의 개념 설명이며 제조 레시피가 아닙니다.

01 / Strategy

작게 시작하고, 근거로 확장합니다.

모델을 만드는 것보다 먼저, 누가 어떤 입력을 보고 어떤 결정을 내리는지 정의합니다. TGV와 다른 문제가 배정되면 주제는 바꾸고 업무 구조를 재사용합니다.

01 · 기본 과제우선

현미경 영상
검토 보조

홀 주변의 선형 결함 후보, 원본 좌표, 품질 경고를 보여 주고 사람이 확인·기각·보류합니다.

시작 조건 · 사용이 허용된 영상. 성능 평가에는 독립 라벨이 필요합니다.

02 · 조건부 확장비교

편광 특징과
현미경 후보 비교

동일 위치 영상을 나란히 보여 주고, 편광 정보가 실제로 검토에 도움이 되는지 같은 평가 표본에서 비교합니다.

시작 조건 · 대응 영상, 촬영 조건, 정합 상태 확인.

03 · 별도 탐색후순위

응력 시뮬레이션
가설 비교

공개·승인 물성, 단순화한 형상과 경계조건을 바꿔 응력 집중의 가정별 차이를 살펴봅니다.

제한 · 계산 결과를 실제 크랙 정답이나 실제 잔류응력으로 취급하지 않습니다.

주장의 경계

현재 크랙 후보 검출, 편광 관측, 미래 크랙 예측은 서로 다른 과제입니다. 미래 발생 예측은 추적 자료가 필요한 미검증 장기 가설이며 기본 제출 범위에서 제외합니다.

02 / AI Application

AI는 이 흐름 안에 들어갑니다.

규칙 기반 영상처리를 비교 기준선으로 먼저 설계합니다. 학습 모델은 라벨 조건이 충족될 때만 비교하고, 사람의 최종 판단과 기록은 유지합니다.

01 / PERMISSION

자료 사용권 확인

출처·사용 범위·비식별 ID 확인. 권한이 불명확하면 입력하지 않습니다.

02 / QUALITY

입력 품질 점검

초점·노출·가림·스케일 확인. 부족하면 재촬영·추가 검토로 분리합니다.

03 / REGION

홀과 ROI 지정

홀 주변 관심영역과 원본 좌표를 유지합니다. 자동 지정 실패 시 사람이 수정합니다.

04 / CANDIDATE

후보 생성

에지·방향성 규칙부터 시작합니다. 라벨에 따라 분류·검출·분할을 비교합니다.

05 / OPTIONAL

편광 정보 비교

대응 영상·정합이 확인될 때만 추가합니다. 실패하면 현미경 단독으로 돌아갑니다.

06 / PRIORITY

검토 순서 제안

유효 영상의 후보 점수를 사용합니다. 저품질·불확실 사례는 별도 큐에 둡니다.

07 / HUMAN REVIEW

사람의 최종 판정

원본과 후보를 비교해 확인·기각·보류하고, 근거와 후속 행동을 기록합니다.

08 / CONTROLLED UPDATE

승인 후 오프라인 개선

승인된 라벨만 재학습에 사용합니다. 독립 평가·현장 승인 후 제한 적용합니다.

온라인 자동 학습은 하지 않습니다. 생성형 AI는 규정·반출 승인이 있을 때 비기밀 문서 정리를 보조할 수 있지만, 크랙 라벨이나 성능 근거를 만들지 않습니다.

확보한 자료에 따라 구현 범위를 고르세요.

아래는 설계 선택 안내입니다. 이미지를 분석하거나 모델을 실행하는 기능은 아닙니다.

추천 범위 / 기본안

라벨이 알려 주는 수준까지만 학습합니다.

규칙 기준선과 같은 분할에서 비교합니다. 데이터 충분성은 임의의 이미지 수가 아니라 독립 시료, 양성·혼동 사례, 학습 곡선으로 판단합니다.

  • 홀·ROI 라벨 → 분류. 정확한 위치 검출로 해석하지 않기.
  • 박스·선 라벨 → 위치 검출. 매칭 기준을 먼저 고정.
  • 픽셀 마스크 → 분할. 경계 불일치까지 평가.
  • 기준선보다 나아지지 않으면 더 단순한 방법 유지.
추천 범위 / 조건부 확장

먼저 나란히 비교하고, 이후에 결합합니다.

같은 시료·위치의 현미경 단독과 편광 추가 방법을 동일 표본·동일 분할에서 비교합니다. 정합에 실패한 사례와 제외 이유도 기록합니다.

  • pair_id, 촬영 방향·광학 배치, 정합 상태 확인.
  • 명암·방향성·패턴 특징은 별도 관측 정보로 표시.
  • 보정·물성 근거 없이 명암을 정량 응력으로 환산하지 않기.
  • 효과가 없거나 확보 비용이 크면 현미경 단독안 선택.
추천 범위 / 문서·흐름 중심

작동 모델 대신 검증 가능한 계획을 완성합니다.

승인 영상에 라벨이 없으면 후보 탐색과 판정 기준 정리까지. 실영상 사용이 불가능하면 합성 예시·정적 스토리보드로 업무 흐름을 설명합니다.

  • 합성 예시에 “합성 예시, 성능 미검증” 표시.
  • 정확도·재현율·수율 개선 수치 제시하지 않기.
  • 입력 오류·보류·사람 검토·수동 대안까지 설명.
  • 공식 필수 결과물인 기획서·발표자료를 우선 완성.
낮은 순위 ≠ 정상

후보 없음·저점수·목록 하단도 정상 판정이 아닙니다. 전체 원본 목록, 미검토량, 보류량을 유지합니다.

후보 점수 ≠ 크랙 확률

검증·보정 전 점수를 확률로 표시하지 않습니다. 검토 순위는 파손 위험도나 미래 발생 가능성과도 다릅니다.

03 / Execution Roadmap

신청부터 발표까지, 실행 순서.

2026년 일정입니다. 공식 안내와 내부 목표를 구분했습니다. 모든 작업은 제안 상태이며 접수·참석·팀 역할이 확정됐다는 뜻이 아닙니다.

11.08–10내부 준비 목표

참석·신청 방식 확인

본선 양일 참석, 개인·동반 신청, 지원서 질문을 확인합니다. 동반 참가자는 각자 신청합니다.

11.11–16내부 제출 목표

검토 후 신청·접수 확인

본인이 최종 검토해 제출합니다. 회사 식별정보·기밀 수치를 제거하고, 접수 개인정보는 저장소에 올리지 않습니다.

11.17 23:59공식 접수 마감

누락 여부 최종 확인

미접수이면 마감 전에 처리합니다. 마감 기준 시간대는 운영사 안내로 추가 확인해야 합니다.

11.19–20공식 선발·팀 안내

참가 상태·규칙·역할 합의

19일 선발·팀 편성 발표, 19–20일 참석 확인·충원. 실제 팀과 제출 형식·발표시간·도구 규정을 확인합니다.

11.21–26내부 준비·연습 목표

공통 준비팩 완성

23일까지 문제정의·업무흐름·검증표를 준비합니다. 이후 기획서·발표 골격, 기밀 점검, 오프라인 파일을 확인합니다.

11.27–28공식 본선 · 무박 2일

배정 문제에 맞춰 제출

1일차 3개 문제 공개 후 지망·추첨으로 배정합니다. TGV가 맞지 않으면 전환하고, 기획서·발표자료를 완성합니다.

2026-11-08 확인된 공식 안내 ↗를 정리한 일정입니다. 최신 변경 공지·선발 메일이 우선입니다. 장소는 충남지식산업센터 예정이며 세부 시간표·공식 발표시간은 미확정입니다. “무박 2일”은 48시간 연속 개발을 뜻하지 않습니다.

04 / Evidence & Validation

효과는 약속하지 않고 측정합니다.

속도가 빨라져도 중요한 결함 누락이 허용 범위를 넘으면 실패입니다. 표본·분할·보류·불확실성을 함께 공개하고 불리한 결과도 남깁니다.

H1 / 기본 가설

누락을 악화시키지 않고
검토시간을 줄일 수 있는가?

수동 검토와 보조 검토를 비교합니다. 승인 영상·독립 판정·검토자가 필요합니다.

현재 상태 · 실행 전, 효과 미측정

H2 / 확장 가설

편광 특징이
추가 정보를 주는가?

같은 대응 표본에서 현미경 단독과 비교합니다. 촬영 조건과 정합 실패도 포함합니다.

현재 상태 · 실행 전, 대응 자료 필요

H3 / 장기 가설

기점의 신호가 이후
크랙 발생과 관련되는가?

기점 무크랙 확인, 추적 기간·부하, 미래 사건 라벨과 시간 누수 방지가 필요합니다.

현재 상태 · 미검증, 기본 제출 범위 밖

독립 평가를 지키는 5가지

  1. 같은 시료·홀·대응 영상·증강본은 같은 분할 그룹에 둡니다.
  2. 학습·검증·최종 평가를 구분하고 임계값은 검증 세트에서만 선택합니다.
  3. 가능하면 AI 출력을 보지 않은 두 검토자가 독립 라벨을 만듭니다.
  4. 오탐·미탐·저품질·정합 실패·보류 사례를 빼고 계산하지 않습니다.
  5. 사람 단독·보조 비교는 제시 순서와 기억 효과를 통제합니다.

측정할 지표 · 실제 결과 없음

  • 확인 크랙 재현율 · 정밀도미측정
  • 관측상 음성 홀 오경보율미측정
  • 보류율 · 미검토량 · 저순위 누락미측정
  • 사람 판정·기록 완료까지의 시간미측정
  • 최종 판정 오류 · 의견 불일치미측정

수치에는 시료·홀·영상 수, 양성·음성·보류 수, 버전과 불확실성을 함께 기록합니다. 미측정을 0으로 쓰지 않습니다.

적용 순서 · 문서·합성 흐름 확인 → 승인 자료의 오프라인 평가 → 실제 판단에 영향 없는 그림자 운영 → 현장·보안 승인 후 제한된 보조 운영. 자동 출하 판정과 공정 조건 변경은 범위 밖입니다.

05 / Deliverables & Decisions

제출물은 명확하게, 책임은 사람에게.

아래는 준비할 항목입니다. 체크 모양은 완료 표시가 아니며, 참가 접수·기획서·발표 파일이 이미 완성됐다는 뜻도 아닙니다.

필수 / 업무혁신 기획서

문제부터 적용까지 한 흐름

사용자·현재 업무·AI 역할·개선 가설·검증·리스크·출처를 연결합니다. 효과 주장은 측정 결과, 목표, 가설 중 하나로 구분합니다.

  • 문제정의 1쪽 + 현재/개선 업무흐름
  • 자료 사용 범위 + AI 입력·출력·사람 책임
  • 기준선·표본·누수·보류·중단 조건
  • 근거·가정표 + 실패 시 수동 대안
  • 작성자 외 검토자의 기밀·근거 확인

  2. 현재 업무와 불편 · 확인할 가정
